# Cognitive Load

## Core idea

Users have finite cognitive resources. UX should preserve those resources for the task itself.

### Intrinsic load
Complexity that comes from the task.

Example:
Filing a tax return is inherently more complex than choosing a theme.

Design response:
- sequence the task
- provide domain-specific guidance
- preserve context
- break complex operations into meaningful stages

### Extraneous load
Complexity created by the interface.

Common causes:
- inconsistent terminology
- excessive decoration
- unclear hierarchy
- unnecessary steps
- repeated data entry
- ambiguous errors

Design response:
- simplify presentation
- remove redundant decisions
- use consistent patterns
- keep instructions close to the action

### Germane load
Mental effort used to build useful understanding.

Support it with:
- examples
- explanations
- comparisons
- progressive disclosure
- feedback that explains consequences

## Practical techniques

### Chunking
Group related information into meaningful units.

### Progressive disclosure
Show what is needed now and reveal advanced options when relevant.

### Scaffolding
Provide temporary support that helps users complete unfamiliar tasks.

### Context preservation
Do not make users remember information that the interface can retain.

### Error prevention
Prevent predictable mistakes where doing so does not create new friction.

## Review questions

- Is the task inherently complex, or is the UI making it complex?
- Which information must be visible now?
- Which information can be deferred?
- Are users being asked to remember information unnecessarily?
- Can related controls be grouped?
- Are instructions understandable at the point of need?
